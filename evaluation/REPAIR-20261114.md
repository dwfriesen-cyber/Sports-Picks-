# Daily Edge value evaluation: root cause and measured repair

## What was wrong

The report required calibrated per-game probabilities and genuine timestamped prices, but the production engine supplies original V6 winners and V7-A ranking scores only. The existing isolated evaluator could settle supplied tickets, not estimate probability or select value. Therefore the repeated NO BET was often **an unfinished evaluation service**, not evidence that a complete price-sensitive market evaluation found nothing worth selecting.

Main report template now distinguishes VALUE EVALUATION BLOCKED from NO QUALIFYING VALUE. The no-ticket safety gate remains intact; no forced parlay, new betting transaction, historical rewrite or model promotion occurred.

## New working research component

`calibration_audit.py` fits a fixed, simple ridge logistic calibration on absolute original V6 margin. This is a **new research model**, not recovered original V3, not V7-A confidence reinterpreted as probability, and not a replacement for any original pick.

Every training result must have a recorded grading time strictly before the target's original freeze. Same-day/future outcomes cannot enter training. Forecast hashes, model identity, winner/margin consistency and pregame timestamps are checked. Duplicate grade revisions are rejected pending explicit reconciliation. All input is read-only, and output goes to stdout.

Protocol fixed before this execution: minimum 50 training outcomes; intercept plus one standardized margin feature; ridge slope penalty 1.0; no hyperparameter/model search; refit separately using only available history. This is retrospective walk-forward analysis of prospectively frozen selections, NOT proof these probability estimates existed at the historical decision times.

## Executed evidence

State commit: `2c463e5865caec89ba31893cae23a073723f8fc1` on `picks-data`.

- 22 immutable NHL slates, 149 original picks.
- 135 outcomes joined to their exact forecast SHA-256.
- 74 evaluated out-of-sample predictions after training eligibility, across 12 dates.
- Brier error: 0.210228 versus 0.217216 for the contemporaneous training-win-rate baseline (lower is better).
- Log loss: 0.607750.
- Exploratory paired date-block bootstrap Brier difference, 10,000 fixed-seed resamples: roughly −0.0196 to +0.0043 at the 2.5/97.5 percentiles. The interval includes no improvement. This small dependent sample does not establish reliable superiority.
- 14 unit tests passed (9 new calibration/source/chronology checks and 5 existing evaluator checks).

No existing frozen pick, grade, cash ledger, hypothetical ticket or production engine changed. Today's research estimates are not published as Value recommendations.

## Reproduce

In an isolated checkout of this branch, obtain a separate read-only checkout of `picks-data` at the exact state commit above, then:

```sh
python -m unittest discover -s evaluation -v
python evaluation/calibration_audit.py --state-root /path/to/pinned-state --source-ref 2c463e5865caec89ba31893cae23a073723f8fc1
```

The output records every prediction's coefficients, training count and latest training-grade time. `--bundle` also accepts the exact `{ref,files:[{path,content}]}` input contract. No paid dependencies, network requests or credentials required.

## Remaining real work, not solved by changing the label

1. A supported automatically archived pregame odds feed, with book/market/selection/timestamp and latency, is not integrated. The current archive tool accepts verified receipts but is not a live collector. Indicative news quotes must not be labeled executable PlayNow prices.
2. Calibration needs prospective shadow validation and reliability/error analysis on a larger independent sample. The current result is explicitly not promoted.
3. A predeclared price-margin policy, uncertainty handling, vig and cross-leg dependence must be validated before hypothetical value tickets are enabled. A simple calibrated win chance is not itself profitability evidence.

The correct present status is **VALUE EVALUATION BLOCKED; research calibration now implemented and measured, price integration/promotion still pending**. A complete evaluation may legitimately conclude no bet on a future day; the repair must never guarantee a ticket.
